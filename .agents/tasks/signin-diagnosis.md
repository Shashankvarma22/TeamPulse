# Google Sign-In Button Diagnosis Report

## Summary
The sign-in button is not working due to **three critical configuration issues** in the Android app that prevent the Credential Manager API from properly initiating Google Sign-In.

---

## 1. Debug SHA-1 Fingerprint

**Found:** `1E:C9:0E:FD:E0:B8:0F:1D:6C:B2:FA:6A:87:8B:1F:EC:4B:B3:4B:CC`

This fingerprint must be registered in Google Cloud Console for the debug build to work.

---

## 2. Root Causes Identified

### 2.1 Fake `mobilesdk_app_id` in google-services.json
**Current value:** `1:973824891796:android:abcdef1234567890`  
**Status:** ❌ FAKE/PLACEHOLDER

The `mobilesdk_app_id` is a hard-coded placeholder. Google Play Services validates this at runtime. The real value has the format `1:973824891796:android:<real-sha1-hash>` and is generated by Firebase/Google Cloud when you register the debug SHA-1 fingerprint.

**Impact:** Google Play Services may fail to initialize, causing silent failures in the credential manager flow.

---

### 2.2 Dummy `api_key` in google-services.json
**Current value:** `AIzaSyDummyKeyForTestingOnlyReplaceThisWithRealKey`  
**Status:** ❌ DUMMY/PLACEHOLDER

The API key is a clearly fake placeholder. While Credential Manager doesn't directly use this key, other Play Services components do during initialization. A missing or invalid key can cause service initialization to fail.

**Impact:** Prevents proper initialization of Google Play Services, which the Credential Manager depends on.

---

### 2.3 Missing SHA-1 Registration in Google Cloud Console
**Current web client ID:** `973824891796-ukjv45oduh113adbr2dq7dhlv3k8t5b2.apps.googleusercontent.com`  
**Status:** ❌ SHA-1 FINGERPRINT NOT REGISTERED

The Credential Manager API (`GetSignInWithGoogleOption`) requires the app's package name and SHA-1 fingerprint to be registered with the web OAuth 2.0 client in Google Cloud Console. Without this registration, the API silently fails and returns `GetCredentialCancellationException`.

**Impact:** The sign-in flow cannot complete even if the user has a Google account and Play Services is correctly installed.

---

### 2.4 Missing OAuth Consent Screen Configuration
**Status:** ❌ NOT CONFIGURED

The OAuth 2.0 consent screen must be published or the user's email must be added as a test user in Google Cloud Console.

**Impact:** The authorization server may reject the sign-in request if the app is not properly authorized.

5. Click **Save and Continue**
6. On the **Scopes** page, ensure the following are added:
   - `https://www.googleapis.com/auth/userinfo.profile`
   - `https://www.googleapis.com/auth/userinfo.email`
7. Click **Save and Continue**
8. On the **Test users** page, add your Google account email address

## 6. Credential Analysis: Why the Provided JSON Works

The user provided this OAuth credential (a desktop/installed-app type):
```json
{
  "installed": {
    "client_id": "973824891796-ukjv45oduh113adbr2dq7dhlv3k8t5b2.apps.googleusercontent.com",
    "project_id": "teampulse-505107",
    "auth_uri": "https://accounts.google.com/o/oauth2/auth",
    "token_uri": "https://oauth2.googleapis.com/token",
    "auth_provider_x509_cert_url": "https://www.googleapis.com/oauth2/v1/certs"
  }
}
```

**Important:** This is a desktop/installed application OAuth credential, not an Android-specific credential. The client_id happens to match the web client ID in google-services.json (`973824891796-ukjv45oduh113adbr2dq7dhlv3k8t5b2`).

**Implication:** The `client_id` is valid and corresponds to a real OAuth client in Google Cloud Console. However:
- For the Credential Manager API to work on Android, this web client ID must also have the app's SHA-1 fingerprint registered.
- The google-services.json must contain the real `mobilesdk_app_id` and `api_key` generated from Firebase/Google Cloud for this specific project.
